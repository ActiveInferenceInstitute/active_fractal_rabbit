# Privacy and Minimization: Synthetic Proxies Do Not Certify Safety

## Scope and Non-Claims Come First

This document defines the privacy and minimization boundary for active_fractal_rabbit. The project operates exclusively on synthetic waypoint data generated by the FractalRabbit simulator. **This document describes proxy measures of re-identification risk in synthetic data, not formal privacy guarantees, not GDPR-compliance determinations, and not differential privacy.** See [empirical_validation_protocol.md](../empirical_validation_protocol.md) for the separate, unexecuted gate required before any real mobility data enter the pipeline.

The key **non-claims**:
- No claim that these measures satisfy GDPR Articles 5(1)(c) or 25, or any regulatory framework.
- No claim that synthetic-data generation itself provides privacy.
- No claim of differential privacy or formal privacy bounds.
- No claim that utility-preserving synthetic trajectory generation, LLM-agent generation, diffusion generation, or foundation-model training removes privacy risk.
- No operational, surveillance, re-identification, or tasking capability is built or intended.

---

## Location Minimization Is a Risk-Proxy Frontier

The core finding is artifact-measured and oversight-positive: **coarsening the spatial-cell label collapses measured re-identification linkability in the synthetic generator.** This is measured via [`linkage_risk_frontier.py`](../../src/active_fractal_rabbit/linkage_risk_frontier.py), which estimates how much identity structure persists in a traveller's coarsened-signature stream under four minimization regimes:

1. **full location**: the spatial cell only (full 16-cell grid).
2. **no_location**: time-of-day, speed, and burst category (location withheld).
3. **time_burst**: time-of-day and burst category (location and speed withheld).
4. **time_only**: time-of-day only (all spatial and speed data withheld).

### Re-Linkage Risk Is a Synthetic Statistic

For each regime, the function splits each synthetic traveller's coarsened-signature stream into an enrollment half and a probe half. The probe is re-linked to the nearest enrollment profile by cosine similarity over marginal signature histograms. **Rank-1 re-link accuracy is the risk statistic.** This measures how uniquely identifiable a traveller becomes under that regime, relative to chance (1 / number of travellers).

### Synthetic Provenance Is Code-Enforced

The linkage function is **gated with a mandatory, code-enforced synthetic-provenance marker** (`synthetic_provenance` parameter). The allowed values are:

```python
_ALLOWED_SYNTHETIC_PROVENANCE = frozenset(
    {"fractalrabbit_fixture", "fractalrabbit_external", "pr_ctrw_synthetic"}
)
```

**Running the frontier on real data requires a deliberate, auditable misrepresentation** rather than an accident:

```python
def _require_synthetic_provenance(provenance: str) -> str:
    if provenance not in _ALLOWED_SYNTHETIC_PROVENANCE:
        raise ValueError(
            "linkage_risk_frontier refuses non-synthetic provenance: this is an oversight-positive "
            "RISK measure over synthetic generators only, never a re-identification tool over real data. "
            f"Got {provenance!r}; allowed: {sorted(_ALLOWED_SYNTHETIC_PROVENANCE)}."
        )
    return provenance
```

### Defensive Nulls Check Power

The frontier report includes:
- **Structure-null**: Shuffle the traveller↔signature association while preserving marginal signature counts and per-traveller counts. This confirms the linkability is genuine identity structure, not a cardinality artifact.
- **Positive control**: Inject a synthetic unique signature into one traveller's time-only stream. The gate must detect this injected uniqueness above the null, confirming the test has power. A failure-to-detect injected signal means "the test is too weak," not "minimization is worthless."

### Outputs Report Aggregate Risk Only

The frontier returns **aggregate per-regime risk numbers only** — never a per-record match score, never a per-real-person association. The positive control reports per-synthetic-identity accuracy over the synthetic IDs only (currently five travellers in the fixture), not real individuals. This asymmetry is intentional: **the output cannot be used as a re-identification tool because it never reports individual match decisions, only aggregate statistics.**

### Minimization Collapses Synthetic Linkability

When the frontier passes both gates:
- Full location carries re-link risk well above the structure-null (confirming strong identity structure with location).
- Minimized regimes (no_location, time_burst, time_only) fall inside the structure-null band (confirming that minimization defeats the weak linker).

**Headline verdict**: "location_carries_relink_risk_that_minimization_removes" (fixture-bounded, synthetic-only).

## EFE-Driven Location Minimization Remains a Diagnostic

The active-inference answer to the same question is measured in expected free energy's currency: information gain in nats. [`efe_location_frontier.py`](../../src/active_fractal_rabbit/efe_location_frontier.py) asks directly: **how many nats does withholding location cost, and does the metadata bundle secretly recover it?**

### Per-Modality Epistemic Value Shows Location Dependence

For each observation step, under a location-blind posterior (metadata-only evidence), the frontier scores the expected cell-entropy reduction from observing:
- Location alone.
- Each metadatum (time_of_day, speed, report_burst).
- The metadata bundle (location withheld).
- The full set (location + all metadata).

**Result**: Location dominates the epistemic budget — on the current artifact it carries essentially the whole joint epistemic value (`location_joint_share` ≈ 1.0 in `efe_location_frontier.json`, with the metadata bundle's mean information gain orders of magnitude smaller) — so withholding location is a large epistemic cost in nats. The exact multiplier is run-dependent; read it from the artifact rather than this page.

### Structure-Destroyed Null Gate Blocks Spurious Recovery

The critical control: **rebuild the metadata emissions from cell-label-shuffled data**, which destroys any genuine state→metadata structure while preserving the marginal shapes. If metadata info-gain exceeds the structure-destroyed null, the expanded fixture supports some metadata-state coupling (likely weak). If metadata falls inside the null band, no detectable coupling exists above the floor.

### Caveats Prevent Operational Claims

On the enlarged fixture, the metadata bundle remains a **failure-to-reject above the structure-destroyed null**: the current artifact reports `metadata_recovery_not_above_structure_null`, while direct location still dominates the joint epistemic value. No real-mobility or surveillance claim is made; the result is a synthetic-generator boundary only.

### Residual Localizability Remains Synthetic

The frontier reports explicitly:
- Fraction of travellers confidently localized **with location** (typically near 1.0).
- Fraction of travellers confidently localized **without location** (typically 0.0–0.1).

This is **residual_localized_without_location**, measured rather than assumed. In the current artifact the residual localization without location is 0.0, so metadata-bundle recovery remains a bounded null rather than a promoted recovery claim.

## Poisoning Robustness Is Data-Integrity Self-Monitoring

[`poisoning_robustness.py`](../../src/active_fractal_rabbit/poisoning_robustness.py) measures a **defensive** question: Does the analyst's own active-inference generative model **detect** when fed tampered or inconsistent input observations?

### Stressors Stay Synthetic

Three crude stressors (never optimized, never emitted by the generator, never made evasive):
- **Teleport**: Jump a cell to the farthest grid location.
- **Label-flip**: Relabel a cell randomly.
- **Subtle drift**: Shift one grid step.

These test whether the filter's per-step variational free energy (surprise) rises when the input is corrupted. **This is not an attack tool; it is a diagnostic self-check.** Operators use it to decide whether to trust downstream analysis when the input data are suspicious.

### VFE Surprise Faces the Markov Baseline

The key comparison:
- **VFE poison detection**: ROC AUC of the generative model's surprise at poisoned steps.
- **Markov baseline**: A cheap first-order Markov model's surprise; if VFE gains over Markov, the active-inference model structure helps.
- **Novelty baseline**: Naive "have we seen this cell before?" detector.

### Structure Nulls and Power Controls Bound Detection

Same S14 discipline:
- **Structure-null**: Shuffle which steps carry the poison label while preserving per-mode and step counts. Destroys the step-poison alignment while keeping marginals.
- **Positive control**: Inject a known surprise spike (2.0 nats) at poisoned steps. The gate must reject (detect the spike), confirming the test has power.

### Diagnostics Stay Configuration-Bound

The verdict is always **configuration-bound**, never a hardcoded guarantee. `poisoning_robustness.py` emits exactly three verdict strings:
- `"gross_and_moderate_poisoning_detected_subtle_is_null"` → gross and moderate stressors separated from Markov; subtle drift did not.
- `"gross_poisoning_detected_label_flip_not_markov_separated_subtle_is_null"` → teleport separated; label-flip detected above chance but not Markov-separated; subtle drift null.
- `"poisoning_detection_regime_changed"` → the default fallback when the mid-rate gates do not clear; a null verdict means VFE did not beat the cheap Markov baseline on this fixture and stressor. This is the current regenerated artifact's verdict (`output/runs/poisoning_robustness.json`).

**Caveat**: Operators should read these as **data-integrity diagnostics specific to this generator and grid**, not as assurance that subtle drift is truly undetectable. Adversarial or real-world corruption may be far more sophisticated.

## GDPR Is Conceptual Framing, Not Compliance

For governance reference, this project aligns its language with two legal anchors—**conceptually only, not as a compliance claim**:

### GDPR Data Minimization Is a Principle Anchor

> Personal data shall be "adequate, relevant and limited to what is necessary in relation to the purposes for which they are processed."

The re-linkage frontier operationalizes this principle in synthetic data by measuring what becomes "not necessary": full location detail is information-rich for re-identification, but time-of-day and burst category alone do not support re-linkage above the null. **This is a proxy measure, not a proof of GDPR compliance.**

### GDPR Design-and-Default Language Is an Anchor

> Data protection principles shall be integrated into the processing, both at the design and implementation stage.

The code-enforced synthetic-provenance gate, positive controls, and structure nulls are **defensive design**: they prevent accidental real-data use and confirm that minimization actually works on this generator, rather than merely describing it in prose.

### NIST Privacy Framework Supplies Risk Vocabulary

The NIST Cybersecurity and Privacy Framework's Privacy Core functions (Govern, Map, Protect, Manage, Measure) inform the language:
- **Govern**: Synthetic-only boundary stated in code; empirical protocol drafted for future real data.
- **Map**: Provenance and modality gates; fixture-bounded caveat.
- **Protect**: Location-minimization frontier as defensive risk reduction.
- **Manage**: Structure nulls and positive controls confirm minimization works, not broken.
- **Measure**: Per-regime risk numbers, resiliency verdicts, evidence-bound claims.

**These are framing references only.** They do not establish GDPR compliance, differential privacy, or any formal guarantee. Real data require the separate empirical protocol ([empirical_validation_protocol.md](../empirical_validation_protocol.md)).

### AI, Cybersecurity, and Commercial-Data Sources Anchor Governance

This project now cites a wider governance source family, still conceptually only:

- **NIST AI Risk Management Framework**: supplies vocabulary for validity, reliability, transparency, accountability, and risk management. It helps name why token provenance, claim ledgers, null gates, and uncertainty reporting matter. It does not certify this benchmark or establish model trustworthiness.
- **NIST Cybersecurity Framework**: supplies govern/map/measure-style language for organizing risk. It does not mean this repository has passed a cybersecurity assessment.
- **DoD Responsible AI implementation guidance**: supplies responsible, equitable, traceable, reliable, and governable principles as responsible-interpretation anchors. It does not approve military use, deployment, targeting, tasking, or operational reliance on this work.
- **ODNI commercially available information materials**: document why commercially available information can raise privacy, civil-liberties, provenance, and minimization concerns. This project does not ingest CAI and does not create an intelligence product; the sources justify caution around commercial location-data analogies only.
- **FTC location-data actions**: show that sensitive location and connected-vehicle geolocation flows can be enforcement-relevant. They do not determine this project's legal compliance, technical validity, or release readiness.

The shared rule is simple: these sources support policy relevance and responsible-interpretation boundaries, not empirical validation, SOTA status, legal compliance, or operational readiness.

Recent trajectory-generation work sharpens the same boundary rather than relaxing it. Utility frameworks, diffusion-based generators, LLM-agent trajectory generators, and mobility foundation models are candidate comparison or generation families only; they do not make synthetic trajectories private by default. Formal differential privacy, when applied to trajectory generation, is a separate mechanism with measurable utility cost and constrained feasibility. The project therefore keeps its own minimization and linkage results as synthetic risk proxies until a separate privacy mechanism and empirical protocol are implemented.

## Dual-Use Boundary Is Oversight-Positive, Not Surveillance Capability

### The Project Does Not Build Operational Capability

- **No re-identification tool**: The frontier returns aggregate risk numbers per regime, never individual match decisions.
- **No surveillance capability**: Linkage and EFE frontiers operate only on the project's own synthetic IDs and coarsened signatures, never on external datasets or real people.
- **No tasking capability**: The poisoning-robustness diagnostic detects input corruption; it does not construct adversarial inputs, does not optimize for evasion, and does not target real agents.
- **No deanonymization pathway**: The project does not attempt to reverse anonymization, crack hashes, or recover withheld fields.

### The Project Builds Bounded Audit Artifacts

- **Defensive risk measurement**: Quantifies how much re-identification risk each observation regime carries, in order to show what data-minimization **protects**.
- **Self-monitoring diagnostics**: Confirms that the analyst's own model detects gross input corruption and that the test has sufficient power.
- **Positive-control gates**: Every null result is paired with a positive control, so failure-to-reject is interpretable as "no advantage here," not "test too weak."

### Governance Operating Principle Keeps Claims Small

**Oversight-positive asymmetry**: The project measures risk in order to **reduce** risk; it produces no tool that would empower surveillance, re-identification, or re-tasking. All outputs are aggregate, all gates are confirmatory, and all caveats are explicit. **The burden is on the analyst to use these diagnostics responsibly, and the code enforces the boundary that they cannot be used on real data without deliberate, auditable action.**

## Synthetic Provenance Defines Data-Governance Entry Points

### Configuration-Level Provenance Starts the Chain

The config key `fractalrabbit.execution` determines the provenance at load time:
- `fixture`: Uses a checked CSV fixture or a built-state snapshot; provenance is `fractalrabbit_fixture`.
- `external`: Builds and runs the pinned FractalRabbit simulator; provenance is `fractalrabbit_external`.

Both are validated against the allowed set before any analysis runs. See [config_schema.md](../config_schema.md) for the full config surface.

### Observation-Pipeline Validation Preserves the Chain

The `observation_sources.load_observation_sequence` function chains:
1. Load config and validate execution mode.
2. Derive provenance from simulator config.
3. Pass provenance marker to any downstream analysis (linkage frontier, EFE frontier, etc.).

**No provenance marker → analysis refuses to run.** This is a fail-safe: if the config or data source is unrecognized, the pipeline halts rather than proceeding silently.

### Output Metadata Closes the Chain

Every frontier and diagnostic artifact includes a `synthetic_provenance` field in its JSON output:

```json
{
  "schema": "active-fractal-rabbit-linkage-risk-frontier-v1",
  "status": "completed",
  "synthetic_provenance": "fractalrabbit_fixture",
  "linker": "weakest-credible: cosine over marginal signature histograms...",
  ...
}
```

Artifacts carry this marker for audit and reproducibility. **A researcher reviewing the manuscript can verify from the artifact JSON that real data were never analyzed under these risk measures.**

## Empirical Data Requires a Separate Unexecuted Gate

This document covers synthetic-data boundaries only. Any future use of real waypoint or mobility data **requires the separate protocol** in [empirical_validation_protocol.md](../empirical_validation_protocol.md), which includes:

- **Claim boundary before data access**: Define a single empirical claim in advance; pre-register it.
- **Data governance and consent**: Documented agreement covering consent basis, permitted analyses, retention, and deletion.
- **Privacy threat assessment**: Coarse spatiotemporal data are insufficient anonymization by default; run explicit uniqueness and linkage assessments.
- **Sampling and external validity**: Document population, sampling frame, and known selection biases.
- **Frozen analysis plan and negative controls**: Same gates as synthetic lane, applied to empirical data.
- **Reporting and null results**: Publish the claim ledger, deviations, and negative results with equal prominence.

**Status: Draft. Not yet executed.** No real-data claims depend on this project.
